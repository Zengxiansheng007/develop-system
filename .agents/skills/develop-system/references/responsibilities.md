# 职责与按需路线

## 责任分工

| 角色/技能 | 专业责任 | 回流内容 |
|---|---|---|
| develop-system | 选择路线、传递上下文、登记帧、协议/版本/依赖检查、状态关闭 | 路由决定与来源引用，不产出专业验收 |
| implement | 实现单个任务或明确规格，相关构建与验证，处理评审发现 | 实现、验证证据、职责完成与验收项结论 |
| implement-spec | 按规格任务图判断就绪任务，协调实现、代码集成及集成验证 | 子帧请求、集成产物与证据 |
| tdd | 失败测试 → 实现通过 → 重构并重跑测试 | 行为测试及各阶段实际证据 |
| diagnosing-bugs | 复现故障、定位原因、修复、原症状及回归验证 | 复现/根因/修复/回归结果 |
| code-review | 分别评审规范和需求符合度，给出技术验收结论 | 两维报告、发现、通过/待修复/无法验证 |
| pr | 编写变更说明、验证证据与风险；按已有授权交付 PR | 描述及实际交付状态 |
| wizard | 引导必须由人完成的环境、凭据、迁移与人工确认 | 向导与实际人工步骤状态，未完成返回等待 |
| retro | 复盘过程并提出规范、工具及自动检查改进 | 有证据的改进建议 |
| 用户 | 明确要求的人工业务验收、决定和必须人工操作 | 真实答复/操作证据 |

测试、构建通过不自动等于需求评审通过。code-review 对规范和需求分别报告；缺少规格不得声称规格维度通过。专业技能只返回其有证据支持的验收项，人工条件不得以技术检查替代。设计/调研等目标由对应专业技能验证自己的交付条件，不强制增加代码评审。

## 主线与辅助路线

- 单任务：implement → code-review → 按交付目标选 pr。implement 内的 tdd/code-review 子帧已完成且版本有效时复用，不机械重复评审。
- 整份规格：implement-spec 判断任务依赖，向总路由请求 implement 子帧；有授权及隔离环境时并行，否则顺序。集成与验证由 implement-spec 专业角色完成，之后 code-review。
- 测试先行：tdd 作为 implement 或 implement-spec 子帧，完成先回流总路由，再恢复父技能。
- 故障：diagnosing-bugs → code-review；发现缺陷回到相应修复技能，再评审新版本。
- 必须人工操作：在需要时插入 wizard；向导产物完成不能解除尚未完成的人工依赖。
- 交付/复盘：按目标选择 pr；用户要求或重复过程问题触发 retro。复盘建议不自动追加范围。

需求/设计/规格/拆分仍由现有技能处理；本次新增专业阶段不会让所有任务都从访谈重新开始。

## grill 完成后的自动路线

仅适用于显式受管流程中的根 grill-with-docs：必要辅助工作结束、需求文档已保存并获当前版本确认后，先登记回流，再选择后续路线。独立 grill 展示候选后等待用户选择；它不因方案确认自动成为受管流程。

- 工作跨会话、需要多个任务及阻塞依赖，或尚需形成持久实施规格时，选择 `to-spec → to-tickets`；有效的同范围、同版本规格和任务图可复用。拆分完成先回流，再按任务形态及授权选择 implement 或 implement-spec。
- 单个明确任务可在当前会话完成，实施约束与验证目标已充分明确且无需另建规格和依赖图时，选择 `implement`。按范围、依赖和资料完整性判断，不以修改文件数或“技能定制”任务类型直接代替判断。具体实现工具由实现技能选择。
- 在回流状态和计划中保留所选路线、理由及输入文档版本；初始范围未知时先安排必要访谈，回流后使用 extend-plan 追加选定路线，避免将 default_flows 的全部候选预设为必做步骤。已有计划依据实际范围与依赖处理，不跳过必要帧。

上述路线在当前已授权目标内自动执行，不为路线选择等待用户。自动路由不生成用户需求确认、测试位置确认或业务决定；确有未答专业问题时按 waiting_user 处理，依赖缺失按 blocked 处理。默认路线不授权部署、远程发布或消息，相关授权由实际执行技能核对。辅助 grill 帧先恢复父任务，父任务回流后再选主阶段。

## 专业协调与总调度

implement-spec 负责任务图与集成的专业判断，总路由负责实际代理分派及持久状态。code-review 的双维评审同理：专业技能提供评审任务，总路由按授权启动工作代理，所有结果先回流再交回聚合技能。专业技能不能绕过总路由自行推进下一主阶段。

顺序执行使用同一代理的明确角色切换，不谎称独立代理评审。未来验收技能接入统一接口后可以承担专项验收，总路由职责不随新技能扩大。
