# 局部作用范围、用户暂停与系统恢复：T01–T08 候选

本候选交付 Issue #2 的局部阻塞隔离、Issue #3 的用户暂停收件、Issue #4 的专业系统恢复、Issue #5 的授权工作树检查记录 v2、Issue #6 的候选证据失效与保留原来源的评审引用、Issue #7 的 registry v3 必需助手与父帧义务、Issue #8 的局部漏登记修正，以及 Issue #9 的[只读迁移预览](migration-preview.md)。创建 state v4 和 protocol_version: 1 的帧/结果；v3 保持只读，旧引擎的公开状态操作拒绝 v4。检查资格见[机器检查记录](check-records.md)，助手资格与明确修正见[扩展接口](extensions.md)。registry v2 快照不可自动续写；#10/#11 的实际采用、回滚及历史兼容，以及 #12 整批集成仍未交付。

## 从事实到就绪

- control 保存用户运行控制；局部 blocked、waiting_user、cancelled 和 completed 携带 findings 保存在专业帧。持久 restrictions 保存缺失能力与重复无进展停止，不通过根 status 放大局部结果。
- ready_steps 和 dispatch 使用所属步骤、depends_on、requires、父子关系及 shared_preconditions 判断影响。计划可声明非空字符串数组 shared_preconditions；同名表示已知共用前提。专业结果声明 block_scope: unknown 时保留未知范围限制，不擅自认定其它工作独立。缺省 local 只表示归属已知，并不忽略声明的共用前提。
- 根步骤默认串行。尚在执行的独立子任务仍占用所属根工作的容量；只剩受阻子项的等待父任务不占执行容量。就绪列表不是并行授权，实际委派继续遵循统一协议。
- 有效在途回传可保存；父帧完成仍要求必要子项及发现已处理。completed 是专业职责完成，不是整票验收。关闭运行仍需要专业来源的完整 AC、真实人工来源及当前证据。
- depends_on 指向已完成但仍有 findings 的步骤时，只有明确 resolves_frames 覆盖其未决发现的修复步骤可使用该职责完成结果。其它依赖者继续受阻；修复结果之后仍须原 assess 来源核对。

## 缺失与重复停止

block 先登记所属步骤/父帧和原因，不创建执行帧或 inline 替代。对于已经登记但文件暂缺的能力，显式 resume 使用与 dispatch 相同的来源解析重新核验；仍缺失、禁用或名称不符时保留限制。同名显式路径不会回退另一个版本。

文件存在但能力漏登记时，使用[扩展接口的明确修正顺序](extensions.md#当前运行漏登记)。该限制保留已有来源授权，register 只解除已解决部分；用户暂停和其它局部/系统限制仍分别生效。

同一所属步骤/父帧、技能、输入、状态及阻塞/产物/检查事实两次无进展，记录局部停止并保留历史。重复事件保持幂等；其它独立工作可继续。resume 不清空重复停止或事件计数；后续处理必须有新的专业依据和有效授权，不能改名重置额度。

## 已保留的边界

用户暂停、取消和完成继续约束全局；根终态不重开。新帧结果缺少或误报 protocol_version、错误身份/输入、被替代帧、失败检查支持 passed、未决父任务及缺少 AC 均不能通过现有完成保护。当前受管 checks 按[机器检查记录](check-records.md)核对原帧工作树授权、实际加载来源及检查时内容；独立记录和历史 v1 不自动成为受管证明。

## 暂停收件与明确继续

用户暂停时，receive 对已派发结果执行与运行中相同的身份、协议代次、输入/证据新鲜度及幂等核对。有效结果保存一次；重复不增加 revision/事件，冲突及过期结果拒绝且权威状态不变。帧记录专业状态，control 保持暂停来源，next_decision 保持 paused。

结果可保存 resolved_findings 与 acceptance_checks，但保存不等于应用：暂停期间 assess、dispatch、complete 均拒绝，父技能不因收件恢复。未完成必要子项和未决发现仍限制父帧完成。重复无进展也仅增加相应局部限制，不覆盖用户暂停。

只有用户明确要求继续后，总路由才调用 resume(revision, user_reference=<真实用户指令来源>)，CLI 使用 --user-reference；缺少来源拒绝。该来源是调用方负责如实提供的审计引用，不是工具认证的用户身份。继续保留有效已收结果、事件与仍有效在途帧，不自动重派或重置额度；随后按现有 assess/完成接口处理结论。系统结论与失效范围按下节处理。

## 系统限制与专业恢复

专业技能在 completed 结果中声明 system_conclusions 数组。设置项包含 restriction_id（该 run 内唯一）、action: set、scope: global、非空 failed_preconditions 数组及 evidence；证据须属于同一结果的当前 artifacts。解除项 action: clear，保留相同 restriction_id、scope、failed_preconditions，并以 blocked_event_id 指向原设置事件。身份、证据或作用范围不符拒绝；失败命令检查不能支持 clear。总路由不单独输入系统事实。

运行中有效声明自动登记；暂停时只留存在原事件。用户明确继续后，按当前来源重新判断：有效解除只清对应系统限制，其它系统/局部限制保持。来源过期或被替代的解除不再有效，原限制重新成为待处理项；设置来源过期时保留 source_current: false 的待核验限制，不把旧事实宣称为当前结论。原事件和曾应用的事件标识保持，不改写历史。

系统限制期间普通工作不派发。恢复步骤在计划中明确 recovery_for（所针对的所有活动限制 ID）、authorization_reference（已有授权来源）和 shared_preconditions（可为空但必须显式声明）。只有与全部失效前提无交集的恢复步骤及其子帧可用该例外，仍遵守依赖与串行容量；局部/未知范围限制继续有效。引用不能新增授权，也不证明调用者身份。用户暂停关闭恢复例外。

resume 的控制恢复与输入失效分别处理。相关文件变化使对应帧、真实后代、depends_on 和 registry requires 前置关系失效；有效独立根工作及独立子帧的结果/在途身份保留。仅因子项变化而失去完成资格的已完成父帧，沿原身份回到待重新判断的 running；这不是父输入本身失效，不能据此向下作废其它有效子项。只重验受影响子项，再取得新的父专业结论；过期必要子项和父原有未决发现仍阻止完成。父的旧系统解除声明不能因新父结果恢复 completed 而复活，系统事实须来自当前最新专业结果。只有来源受到影响的验收结论失效；明确局部/未知限制不会被 resume 清除。哈希不证明环境健康，环境变化由专业结果声明。

活动系统限制通过 next_decision: system_restricted、restriction_ids 和原因显示；无就绪工作时读取该解释并等待新的专业依据或用户输入，不重复派发。关闭运行要求所有系统限制和原有必要工作已解决；终态不会因回传或恢复重开。
