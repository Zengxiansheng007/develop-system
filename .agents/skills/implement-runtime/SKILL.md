# Local implement runtime extension v1

**Managed tasks:** before dispatching a new implement step, declare its required runtime coverage using [managed contract v1](../runtime-verify/references/managed-contract.md). Execute the registered runtime-verify helper and return its professional envelope before code-review. Preserve every original managed command check. Existing runs without this opt-in contract retain their original semantics; adopting it requires a separately authorized versioned migration, which this extension does not perform.

This sibling directory is local source, outside the upstream `implement/` replacement boundary. Preserve the upstream workflow, existing local adaptations, TDD, type checks, project mandatory checks, and Standards/Spec review. The only upstream addition is the marked loading block. Skill loading alone proves no runtime outcome.

1. **Plan before implementation.** Read [runtime-verify](../runtime-verify/SKILL.md) and its request contract. Map task acceptance IDs to real entry, working directory, independent expected business results, success and affected abnormal behavior, real/simulated dependencies, authorization, evidence location and owned cleanup. Reuse approved seams; ask only for genuinely missing requirements/permissions. Record gaps; never derive expected values from the candidate's output. For non-runnable changes, record why runtime is inapplicable and retain every previously required check.
2. **Verify the candidate before final review.** Invoke the independent runtime capability against actual changed content (including relevant uncommitted source, tests, configuration and dependencies). Use project execution tools and explicit argv/cwd. Keep original failures, then create new evidence for repairs. Required failure, unavailable dependency or missing execution means **运行未验收**; code may still be delivered with that limitation. A zero command exit is not business acceptance.
3. **Review current evidence.** Read [the reuse and repair contract](../runtime-verify/references/reuse-contract.md) for existing evidence or review repairs. Give code-review the actual runtime result and original receipt paths, candidate identity, project check evidence and unresolved gaps. Runtime conclusions remain separate from Standards and Spec. Preserve genuine findings; repair with TDD, reverify affected behavior, retain eligible original executions, and obtain a review of the repaired candidate. When asked to review a supplied candidate first, obtain its runtime evidence and actual review before repairing it.
4. **Complete honestly.** Report code delivery, professional responsibilities and runtime acceptance separately. Missing runtime invocation/evidence cannot pass a required acceptance item. Only a real user decision can defer or change requirements: preserve original requirements and the exact decision reference, and report adjusted scope explicitly. Record nonapplicability without manufacturing a run. Standalone use returns directly to implement; no synthetic develop-system run or managed check is created.

Security differential audit is **explicit-only**. Only when the user explicitly requests that independent audit, read [security-differential-audit](../security-differential-audit/SKILL.md) and apply its comparison-input contract. Security-related task wording does not select it, create an audit obligation, or mark it done. Runtime verification grants no installation, deployment, production write, global modification, data export or publication authority.

For an upstream update or overwritten entry, follow [the reviewed restoration protocol](references/upgrade.md). Prepare the local backup and reviewed three-way merge before replacement, then restore exactly one hook. Missing references or conflicts block restoration. A restored entry remains runtime-unqualified until fresh implement-entry execution proves the required behavior.
