## Problem Statement

develop-system 已能保存专业回流并完成本地整票验收，但将交付事实反映到 GitHub 仍需额外人工指令。人工补同步容易漏掉验收项勾选、证据摘要或待执行标签；直接使用 PR 关闭关键词，又可能在实际合并提交 CI 通过前提前关票。

用户需要在不修改 Matt 工程 Skill 的前提下，由 develop-system 自有层自动处理明确绑定工单的完成同步。专业职责完成、整票验收、关闭资格和远端已同步必须分别表达；超时、停止与人工干预都不能制造成功。

## Solution

增加按项目启用的工单同步能力。项目明确启用后，仅纳管随后新建并明确绑定的运行；每票绑定一个最终交付 PR，多票可共享 PR。只有本票完整验收有效、PR 合入约定目标分支、该实际合并提交上全部配置必需 CI 通过，才自动更新原正文中已映射验收项、证据摘要、配置允许清理的标签，并以 completed 关闭。

仅在 Codex 正在处理该项目任务时同步。停止或离线时没有后台动作；下次明确继续时先读远端，补缺少操作。父规格单独满足其自身整批验收和交付条件；人工重开后只暂停该票，明确重新接管才恢复核对。

## Implementation Decisions

### Module 与 Interface

- 建立 develop-system 自有工单同步 Module，集中配置校验、工单绑定、关闭资格、受限正文变换、同步待办和补同步。调用方只需使用项目配置/绑定、同步一次、读取状态及明确重新接管的公开 Interface；内部如何拆分由实现确定。
- 自动同步与继续补同步跨同一个主 seam，调用者和行为测试使用相同 Interface。依赖以显式对象传入：RunStore 验收来源、GitHub Adapter、持久化和时钟；不在测试中替换私有规则函数。
- RunStore 继续是运行身份、专业回流、验收及授权的唯一执行权威。同步 Module 只保存远端进度及其来源引用；不得另写专业通过断言，或将同步记录当作可续跑开发账本。
- 复用 RunStore 现有归属、输入版本、证据新鲜度、必需辅助职责、发现与专业验收校验。在需要单票验收投影时增加只读公开查询，并与运行完成共享相同资格规则；不在同步调用方复制一套宽松验收算法。
- 单票绑定固定该票全部 AC 与必要工作闭包、原 run/输入版本、专业结论及候选身份。不能只选择若干已过 AC；完整性无法核对时保持待办。批量子票可在自身闭包满足后具备资格，父规格仍独立检查整批要求。

### 配置、启用与绑定

- 项目配置使用独立版本化格式，至少固定项目身份、GitHub 主机与仓库身份、目标分支、非空必需 CI 选择器、允许清理标签、连接引用、正文单写入约定及明确启用依据。凭据值不属于配置。
- 默认关闭。当前规格发布不启用配置；未来项目负责人明确启用时形成可追溯的启用代次。首接项目是 Zengxiansheng007/develop-system，目标分支 main。
- 新运行创建时固定启用代次与纳管资格，随后仅在该资格下补齐明确工单绑定。不能仅比较可修改时间戳、根据最新运行猜测或事后给历史运行补写“新运行”身份。缺资格的新旧运行保持原行为。
- 每票绑定仓库/Issue 稳定身份、原运行、完整验收映射、唯一最终交付 PR 和正文映射基线；父规格显式标记，不能从引用或子票数量推断。Issue 与 PR 类型必须分别核对。
- 多票共享 PR 时，各自保留独立资格、更新范围和进度。已知重复或冲突绑定拒绝写入；同编号不同仓库不共享身份。
- 项目禁用、配置或绑定发生相关变化时停止使用旧资格。重新启用、继续或更换连接不自动解除工单人工暂停；扩大仓库、分支、CI 豁免或重新接管仍需有对应明确依据。

### 验收与交付资格

- 专业职责完成不等于整票验收。专业依据必须对应原票、完整 AC、当前输入与受测候选；未决必要工作、辅助职责或发现，以及缺失人工验收，均不能用行政同步补足。
- 未提交候选的原验收可以保留，但最终关闭前须有可核对关联，证明实际交付 PR 对应已验收内容。后续相关源码变化、冲突修复或候选替换不能沿用失效结论；缺专业依据时等待定向核验，不自动重跑开发。
- 读取最终 PR 的实际合并事实、目标仓库/分支和合并后的交付 SHA。支持 GitHub 普通 merge、squash、rebase 的实际结果；不使用合并前临时 SHA、移动分支 HEAD 或另一个 PR 的提交。
- 必需 CI 选择器包含可区分来源的检查身份。GitHub Actions 至少关联配置工作流、目标分支事件、交付 SHA、作业/矩阵身份及运行尝试；其它受支持检查明确上下文和来源。不要仅按展示名称或任意一条绿色结果判断。
- 所有配置项都须在该交付提交上有明确成功结论。缺失、歧义、排队、执行中、失败、取消、中性或整项跳过均不通过；成功作业内单个测试的平台条件跳过与整项 CI 跳过分别表达。
- 查询覆盖必要分页与当前相关重跑；较新相关尝试未完成或失败时不得回退挑旧绿灯。PR 阶段绿灯不能替代合入目标分支后的配置检查。
- 首接项目沿用既有 Check skills 的 Windows 与 Ubuntu 矩阵；实施接入时核对实际工作流和远端作业身份，不根据本机平台跳过其中一项。
- 父规格独立核对全部自身验收、整批交付与对应 CI；共享 PR 或子票 closed 只提供关联事实。

### 状态含义、生命周期与兼容

| 概念 | 含义及推进规则 |
| --- | --- |
| 未纳管 | 项目未启用、无合法新运行资格或未绑定；不得远端写入 |
| 同步待办 | 尚缺交付条件、远端步骤未完成或结果未知；保留原因与已确认步骤 |
| 工单人工暂停 | 本功能关闭后发生外部重开；禁止该票自动写入，直至明确重新接管 |
| 正文冲突 | 可识别的正文/映射变化；停止该票写入，保存差异，按当前内容核对后才可继续 |
| 已同步 | 允许字段与关闭结果均已读回核对；仍须在后续处理时识别人工重开 |

- 上述为远端同步状态，不映射为原开发运行失败、恢复或重开。原 state v4、registry v3、结果协议代次及历史格式不因新增同步记录自动升级。
- 同步记录单独版本化，引用原运行及专业依据，不复制其执行权威。缺失或未知格式不自动补造；锁/revision、原子保存和冲突拒绝沿用仓库已有模式。
- 在新运行创建、有效整票/整批验收记录可用、交付事实更新及用户明确继续该项目任务时，由自有调度层调用同一同步入口。只处理明确纳管对象；不扫描历史运行补接管。
- 主动用户暂停或取消期间不发起新的同步写入，已在途请求只核对保存回执；局部同步失败不阻塞独立授权工作。停止、仅打开应用或导航入口不触发同步。
- completed 运行允许通过独立补同步入口读取原事实并处理远端待办，不调用 RunStore.resume、不重建运行，也不改变其终态、证据或额度。
- 一轮同步采用有限请求与总执行时限；相关超时和限流参数有正的有限默认值与测试。CI 未完成时记录待办并结束本轮，不持续轮询、后台等待、自动重跑 CI 或启动下一开发票。

### 远端写集、去重与恢复

- 写前先读实际 Issue、正文、标签、关闭/重开历史及既有同步记录；核对归属、启用、人工暂停、验收、PR、CI 和正文基线后才产生受限写集。每次恢复及最终关闭前重新核对相关条件。
- 原正文只勾选准确映射且已通过的条目。映射固定条目标识、预期文本/上下文和基线；重复文本、条目移动或内容不符不能按旧行号盲勾，也不以模型近似匹配代替确定映射。
- 证据摘要采用正文中的一个有稳定标识的受管摘要区，首次可追加，后续核对后更新同一区域；不追加重复评论。摘要包含实际通过项/必要证据引用、最终 PR、交付 SHA、必需 CI 结果链接和同步事实，不改变无关正文。
- 默认使用按名移除配置标签的操作，避免替换全部标签集合。只修改允许正文、受管摘要和配置标签，最后才请求 closed/completed；负责人、里程碑、无关标签和标题不在写集。
- 本地先持久化操作意图、预期前后内容与来源，再发送请求，读回后确认成功；中断或响应未知时先核对远端。已成功步骤不重复，缺少步骤才补，不能将部分成功报告为已同步。
- 多个本地调用按同一纳管工单串行并校验记录版本。标识与正文摘要只用于归属和去重，不能单独证明验收或请求来源；不宣称跨系统事务或远端 exactly-once。
- 对超时后已生效的正文/标签/关闭保留真实结果；如果无法区分未生效与生效后被人工改变，保留未知，不强制覆写或无条件重发。读回不一致时停止后续关闭。
- 请求缺权限、限流、网络错误或必要分页不完整时留下可解释待办；遵守服务等待指示，不无限重试、不读取额外凭据材料、不重置开发额度。

### 人工干预与并发取舍

- 保存本功能关闭的可核对操作来源与远端关闭/重开事件关联。以后即使当前又变成 closed，也要识别该次关闭之后发生过的外部重开；不能只看当前 state。
- 识别到本功能关闭后的外部重开，立即保存工单人工暂停并保留人工状态。项目启用、再次继续、旧条件满足均不能解除；同一账号也可能有人手动操作，不能仅凭 actor 相同判断为本功能写入。
- 明确重新接管需有针对该票的真实用户依据，接管后核对当前正文、验收、PR 和 CI。关闭来源或事件区间不明时保留未知，不猜测接管。
- 人工或其它机制已经关闭的工单不被重开或冒称本功能已完成。原生关闭关键词/自动关闭关联不得由本功能生成来绕过合并后 CI；自有调度与 PR 发布交接应传递此限制，Matt 工程 Skill 不改。发现已有提前关闭配置时报告冲突，不静默改写人工 PR 描述或已发生状态。
- 项目参与者约定同步写原正文期间不并发编辑。写前重读、写后核对；检测正文或映射变化时暂停该票并保留差异。该约定不是强制锁，重读和写入之间仍有不可保证的覆盖窗口；不得声称任意并发零覆盖。

### 所有权、交付与实施顺序

- 允许改动 develop-system 自有调度代码、运行查询/接入、独立工具与配置，以及必要的自有协议文档、测试和打包验证。其它 24 个随包 Skill 目录全部作为本批受保护集合，包含 implement、implement-spec、code-review、tdd 及其辅助资源、策略、来源和许可证；保存实施前实际文件集合及字节指纹，交付时核对无增删改。
- 不修改上游导入 provenance 或历史证据；源码候选来自本独立仓库，生成包从规范源码创建。全局已安装 Skill 是运行基线，不作为本批编辑对象。
- 按可独立验证的行为切片推进：项目配置/新运行绑定与验收投影 → PR/CI 资格和 Adapter 契约 → 正文/标签/关闭与恢复 → 人工干预及调度生命周期 → 保护检查、生成包与首接配置模板。每步同步直接消费者，不能将前序未验证行为推到最后集成。
- 首接交付提供默认禁用、目标清晰的配置模板和操作说明，不在本轮规格发布时启用或接管现有真实运行。实际启用明确后才允许新运行自动同步；无需再逐票确认已授权范围内操作。
- 不以版本升级、安装或关闭旧票作为开发完成依据；必要关联测试、独立 Spec/Standards 审查及下面全部验收项绑定固定候选后才交付。

## Testing Decisions

### 已核对的 seam 与方法

用户已在本轮测试入口核对中选择“采用这组入口”：主 seam 是 develop-system 自有的“同步一次／继续补同步”公开 Interface，使用真实临时 RunStore 与可控制的 GitHub 测试替身，观察远端字段、持久待办及工单人工暂停；补充 GitHub 传输契约与 Matt Skill 内容保护检查，不绑定内部函数。

沿用既有工作流测试的临时项目、真实文件、专业结果夹具、锁/revision、重复事件、证据失效及终态保护先例。夹具显式标注为专业结论测试数据，不声称调用真实模型。不要给每个内部辅助函数建立镜像测试，也不把临时 JSON 手工改为 passed 代替真实 RunStore 流程。

采用 TDD 垂直切片：每次从一个外部行为的失败测试开始，最小实现通过后再必要重构及相关复验。测试替身控制 GitHub 状态/事件、分页、响应丢失、重跑和正文冲突；测试同时检查可观察结果及不应发生的远端写入。

传输 Adapter 用受控 HTTP 响应与请求捕获验证真实序列化、分页、错误/限流和脱敏，不仅测试高层假对象。最低权限按所用端点落实：Issue 写入，以及 PR、提交/内容、CI/Actions 和事件所需读取；不请求合并、推送、工作流写或管理权限来代替功能实现。

### 原需求验收条件

以下保留已确认需求 v1.0 的 AC-001–AC-023 与 REQ 映射。这些是未来功能验收目标，本次只编写/发布规格，未运行功能测试。

- **AC-001 / REQ-001**：实施前后比较受保护 Matt 工程 Skill 文件，新能力交付时这些文件内容不变；受保护清单在技术规格中固定。验证：文件差异检查。
- **AC-002 / REQ-002**：缺整票验收、PR 合并或对应 CI 任一条件时，不产生本功能的完成关闭；不相符或已失效的专业依据不能充当本票验收。
- **AC-003 / REQ-002**：启用、绑定与更新范围合法且三项交付条件有效时，指定工单可更新并关闭，读回结果与报告一致。
- **AC-004 / REQ-003**：两个项目使用不同仓库、相同工单编号时，只作用于对应项目的明确绑定；首接仓库为 Zengxiansheng007/develop-system。
- **AC-005 / REQ-004**：Codex 停止期间，即使 PR 合并或 CI 通过也不新增后台动作；下次继续重新核对并补同步，不假称停止期间已执行。
- **AC-006 / REQ-005**：子票均关闭但父规格缺自身整批验收或交付条件时，父规格不自动关闭；父规格条件满足后才按其绑定同步。
- **AC-007 / REQ-006**：只勾选有有效通过映射的条目、只清理配置允许的标签；摘要对应实际验收、PR 与 CI，且不夹带完整本地台账、日志、私密路径或凭据。
- **AC-008 / REQ-006**：在单写入约定下，无关正文、未映射人工条目、其它标签、负责人和里程碑不被顺带修改；正文并发边界同时适用 AC-021–023。
- **AC-009 / REQ-007**：未启用项目或未绑定工单不自动写入；项目明确启用后对范围内工单不逐票确认，不扩展到其它项目或工单。
- **AC-010 / REQ-008**：最终 PR 候选 CI 已通过，但实际合并提交 CI 未通过时不关闭；其它提交的绿色结果不能冒充该提交的结果。
- **AC-011 / REQ-008**：配置的全部必需 CI 在对应提交上通过才满足条件；缺失、未完成或不通过结果不算通过，不能只取任意一条历史绿色记录。
- **AC-012 / REQ-009**：正文、摘要、标签、关闭部分步骤已成功后中断，继续时先查远端，只补缺少步骤，不重复已完成摘要或更新。
- **AC-013 / REQ-009**：关闭请求超时、结果未知时，不直接推定成功或失败；继续后先核对实际状态。原专业验收及开发额度保持，无法识别的外部变化不被强行覆盖。
- **AC-014 / REQ-009**：相同同步意图再次处理且目标字段已一致时，不重复产生相同更新；缺权限或必要材料时留下待办及原因，不制造全部成功。
- **AC-015 / REQ-010**：本功能关票后人工重开，后续继续仍保留开放并暂停该票写入；独立工单仍可处理。
- **AC-016 / REQ-010**：项目启用、再次继续或旧关闭条件仍成立均不代替明确重新接管；接管后重新核对，不沿旧状态直接关闭。
- **AC-017 / REQ-011**：启用前已存在的历史运行不被扫描后自动接管，原状态、事件、证据、授权与额度保持。
- **AC-018 / REQ-011**：仅已纳管新运行的待办可补同步；不通过恢复开发、迁移 schema、重建或改名运行实现补同步。
- **AC-019 / REQ-012**：同一最终交付 PR 对应多票时，各票及父规格分别核对自身验收，不因共享 PR 批量推定通过。
- **AC-020 / REQ-012**：一票多最终交付 PR、无 PR 和跨仓库交付明确解释为超出首版范围，不擅自重写关联或制造合格依据。
- **AC-021 / REQ-013**：单写入约定下正常读取、受限勾选、写入和核对可完成；更新范围不扩大到其它正文内容。
- **AC-022 / REQ-013**：读取后检测到正文或映射变化，停止该票当前同步，保留冲突与未完成步骤，不以旧副本强写；独立工单不受牵连。
- **AC-023 / REQ-013**：文档和交付明确该约定不是强制锁，不宣称任意并发编辑下绝不覆盖；用受控场景验证可检测冲突，与不可保证的并发窗口分开说明。验证：文档检查与受控冲突场景。

### 技术验收补充

下列 TC 是上述需求与技术选择的验证细化，不改变业务决定或原 AC 编号。

- **TC-001 / AC-002、AC-003、AC-006、AC-019**：真实临时 RunStore 中，单票完整 AC/必要工作未满足、辅助未回流、未决发现、失效候选或人工项缺来源均拒绝关闭；合格独立子票可同步，父规格不能借用其通过结论。同步请求不能自带 passed 断言顶替专业来源。
- **TC-002 / AC-009、AC-017、AC-018**：默认禁用；启用前运行和无纳管资格者不写入，修改时间戳也不能成为新运行。合法启用代次下创建的新运行可绑定；同编号不同仓库、绑定冲突和相关配置漂移均被识别。
- **TC-003 / AC-010、AC-011**：覆盖 merge、squash、rebase 的实际交付 SHA；错误分支、PR 临时 SHA、另一绿色提交、同名不同来源 CI 均不通过；覆盖分页、矩阵缺项、更新重跑 pending/failed、整项 skipped 与作业内平台条件跳过的区别。
- **TC-004 / AC-007、AC-008、AC-012、AC-014、AC-021**：从原正文确定映射勾选、单个摘要区及按名标签移除观察允许写集；重复执行无重复摘要；未映射条目和其它元数据不变；缺任一必要步骤不得报告全部已同步。
- **TC-005 / AC-012、AC-013、AC-014**：在正文、标签、关闭每个请求前后分别模拟中断/响应丢失；新实例继续先读远端，只补缺失步骤。关闭成功后本地回执保存前崩溃，以及无法区分的外部改动，分别覆盖真实核对和未知保护。
- **TC-006 / AC-015、AC-016**：本功能关闭后外部重开、同账号手动重开、两次观察间重开又关闭均保持人工暂停；明确接管重核条件，缺事件区间时不猜。其它独立工单继续；人工/原生先关票不冒称本功能成功。
- **TC-007 / AC-005、AC-009、AC-018**：生产调度接线确实在允许节点调用主入口，停止、导航、用户暂停/取消不发起写入；completed 运行补同步前后原状态/事件/授权/额度字节不变，不调用 resume。CI 未通过即返回待办，时限/限流有界，无后台任务或自动 CI 重跑。
- **TC-008 / AC-022、AC-023**：读取后、写前及写后可检测的正文/映射变化触发该票冲突保护；重复条目与旧行号不可盲写；测试和说明明确区分可检测冲突与不可保证的并发窗口。
- **TC-009 / AC-001、AC-007**：固定候选及生成包核对全部受保护 Skill 的文件集合/字节不变，provenance 不变；新增配置、待办、摘要与异常输出不含凭据、完整环境、私密本地路径或原始日志外发。
- **TC-010 / AC-003、AC-004、AC-014、AC-017**：持久化并发冲突、未知记录版本、连接能力缺失、请求失败/限流均留下准确待办且不扩大作用范围；单票执行串行，生成包与规范源码的公开行为一致，Windows/Ubuntu 关联检查通过。
