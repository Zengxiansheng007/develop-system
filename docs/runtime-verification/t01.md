## Reuse decision and provenance

The owning source was inspected at develop-system `a0a0ada94c3101f1663ea7288aa1ad630cdc9c2f` (MIT): `record_check.run_record` already executes explicit argv/cwd with bounded timeout and exclusive new receipts; `check_binding.source_inventory` already checks authorized candidate paths and fingerprints dirty/new content. Reuse both instead of building another subprocess executor. The only recorder adaptation is an independent-only callback before persistence, because the existing recorder wrote raw output and cannot itself judge business assertions. Managed behavior and default callers retain their contract.

The local policy does not copy the upstream implement workflow. The immutable upstream import remains mattpocock/skills `4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d`, MIT, with existing per-skill LICENSE/source.json untouched. New directories keep the repository MIT license and explicit local origin. Existing mature code supplies execution and source safety; the new code covers only the missing business-plan mapping, output assertion, cleanup ownership, redaction and independent result semantics.

Use the installed CPython **3.11.9** standard library (PSF license, no vendoring or new package); reviewed [subprocess documentation](https://docs.python.org/3/library/subprocess.html) and the [v3.11.9 license](https://github.com/python/cpython/blob/v3.11.9/LICENSE). Python recommends `subprocess.run` for supported foreground calls, matching the existing runner. Windows argv/cwd/UTF-8 behavior is exercised with installed **Node v24.14.0** as a non-Python fixture entry. Node is test infrastructure, not a new bundled dependency. Batch-shell entry and descendant/service lifecycle require a dedicated adapter and are not claimed. Mature upstream research on broader/security runners did not justify importing a second engine or license surface; the existing applicable runner ends selection here.
