## 正常、异常与边界流程

### 正常同步

1. 项目已明确启用，运行属于首版纳管范围，工单和最终交付 PR 已绑定。
2. Codex 执行本项目任务时，核对当前远端状态、原专业验收、PR 实际合并事实及对应必需 CI。
3. 条件未满足则记录原因和待办，按原任务停止边界交付；不持续等待、不后台续跑。
4. 条件满足且没有该票人工暂停、正文冲突或其它未解决限制时，生成受限更新，仅处理允许字段。
5. 读回实际结果，记录已确认成功及仍未完成的步骤。只有核对完成才能报告远端已同步。
6. 父规格单独判断其整批验收及交付条件；共享同一 PR 不共享“已验收”的推定。

### 停止与继续

停止期间没有后台动作。后续继续先检查原同步待办及远端事实，重新核对当前条件，只补仍缺的操作。已纳管新运行的本地开发终态和原专业记录保持；补同步不通过恢复、重建或改名开发运行实现，也不作为第二执行账本。

### 部分成功、超时与权限失败

- 请求超时不证明远端没有生效。再次尝试前先查实际状态，避免重复摘要或重复更新。
- 保留已成功操作，记录尚未确认完成的步骤；不能把部分成功报告为全部完成。
- 权限、限流、接口错误或无法读取必要材料时，不捏造通过、不无限重试，保留该票待办并说明原因。独立且已获授权的其它工作不因此全局停止。
- 本地验收事实和原开发额度不因同步失败撤销、重做或清零。同步不自动调用实现、全量测试或部署来“修复”远端写入失败。
- 无法区分“请求已生效后又被人工改变”与“请求未生效”时，保留未知并核对，不凭当前字段强行覆盖。

### 人工重开

本功能已关票后，人工重新打开该票，暂停其后续自动同步。项目保持启用、再次继续或旧关闭条件仍成立，都不解除该暂停。只有真实明确的重新接管要求才恢复核对；接管后仍须检查当前验收内容、PR 和 CI，不沿旧状态直接再关票。其他工单可继续。

### 正文单写入约定与冲突

项目参与者约定：同步写入 Issue 原正文期间，不并发编辑该正文。写入前重读、写入后核对；发现正文或映射发生变化，停止该票当前同步，保留差异与待办，不用旧副本强行覆盖。后续按当前内容重新核对，人工重开的明确接管要求仍独立有效。

这是协作约定，不是系统强制锁。GitHub 接口未提供已证实的正文原子条件写入保证；其他人在重读和写入之间编辑时，仍可能发生无法预先识别的覆盖窗口。不得将检查通过描述为对任意并发写入的保证。该边界已由 Q13=A 接受。

### 首版不支持的交付

历史运行、一票多个最终交付 PR、无 PR 和跨仓库交付，不自动进入首版完成关闭流程。报告范围限制，不自动转移仓库、合并 PR、改写关联、制造验收依据或创建新运行替代原历史。

## 非功能要求

- **可追溯**：区分原专业结论、原证据、远端同步步骤与实际读回结果；失败和未知保持可见。
- **可恢复与去重**：相同意图重复处理时，先核对已完成动作，只补缺少步骤；待办不授予新的开发执行权限。
- **内容保护**：在约定的单写入范围内，变更集只包含已批准字段；发现可识别变化时暂停。并发保护的局限按 Q13 明示。
- **授权与敏感资料**：复用已批准连接或凭据引用；凭据值不进入需求、配置、摘要、日志或仓库。本需求不新增凭据读取、权限提升或额外资料外发。
- **兼容性**：原运行、帧、事件、证据、授权、终态及额度保持；首版不自动采用旧运行或修改其 schema。
- **资源与等待**：不创建后台服务或持续轮询，不承诺即时关票。请求超时和限流处理由技术规格固定，本需求不设未经讨论的性能、时限或重试次数。
